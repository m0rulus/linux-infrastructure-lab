# RED OS 8  Infrastructure Configuration & Security

Учебный инфраструктурный проект, посвящённый установке, настройке и базовому усилению безопасности сервера на базе **RED OS 8**.

В рамках проекта реализованы управление пользователями и правами доступа, настройка файловых систем, веб-сервера Nginx, механизмов SELinux и Linux capabilities, а также сбор технических свидетельств выполненных проверок.

> Проект выполнен в рамках магистерской программы по информационной безопасности. Это самостоятельная учебная работа, демонстрирующая практические навыки администрирования Linux и настройки инфраструктуры.

## Цели проекта

- Развернуть минимальную серверную систему RED OS 8.
- Настроить дисковую подсистему и постоянное монтирование файловой системы.
- Организовать разграничение доступа пользователей к данным.
- Настроить Nginx для обслуживания веб-контента из нестандартного каталога.
- Применить механизмы SELinux и Linux capabilities.
- Настроить базовые требования к парольной политике и локальной аутентификации.
- Сохранить результаты проверок и подготовить воспроизводимую техническую документацию.

## Реализованные задачи

### 1. Установка и базовая настройка системы

- Установлена RED OS 8.0.3 Minimal без графического интерфейса.
- Настроено имя узла `mephi-2026.domain.local`.
- Выполнено обновление системных пакетов.
- Установлены необходимые инструменты администрирования.

### 2. Управление пакетами

- Установлены Nginx и `libcap-ng-utils`.
- Пакет tcpdump загружен через `dnf download` и установлен из RPM-пакета с использованием `rpm`.
- Сохранена история операций DNF.

### 3. Дисковая подсистема

- Подключён дополнительный виртуальный диск.
- Создан раздел `/dev/sdb1`.
- Создана файловая система ext4 с меткой `MEPHI_WEB`.
- Настроена точка монтирования `/mephi-web`.
- Добавлена запись в `/etc/fstab` с использованием метки файловой системы.

### 4. Веб-сервер Nginx

- Сервис Nginx запущен и включён в автозапуск.
- Корневой каталог веб-сервера изменён на `/mephi-web`.
- Проверена корректность конфигурации Nginx.
- Подготовлена тестовая HTML-страница.

### 5. Управление пользователями и доступом

Созданы две категории пользователей.

**Разработчики:**

| Пользователь |  UID |
| ------------ | ---: |
| user1        | 5501 |
| user2        | 5502 |
| user3        | 5503 |

Группа: `developers`.

**Кураторы:**

| Пользователь |  UID |
| ------------ | ---: |
| curator1     | 5504 |
| curator2     | 5505 |

Группа: `curators`, GID 4444.

Для каталога `/data/mephi-2026` настроены права доступа и ACL:

- разработчики имеют права чтения и записи;
- кураторы имеют права чтения без записи;
- остальные пользователи не имеют доступа;
- установлены default ACL для наследования разрешений новыми объектами.

Проверены сценарии доступа разных категорий пользователей.

### 6. Linux capabilities

Для tcpdump настроены capabilities:

```text
cap_net_admin,cap_net_raw=eip
```

Проверено выполнение tcpdump от имени непривилегированного пользователя. Захват пакетов выполнен без использования SUID-бита.

### 7. SELinux

- Проверен режим работы SELinux.
- Система работает в режиме `Enforcing`.
- Для содержимого `/mephi-web` настроен тип SELinux `httpd_sys_content_t`.
- Контексты файлов восстановлены с использованием `restorecon`.
- Проверена работа Nginx с нестандартным корневым каталогом.

### 8. Политика паролей и локальная аутентификация

- Установлена минимальная длина пароля 12 символов.
- Максимальный срок действия пароля настроен на 90 дней.
- Для кураторов настроено ограничение локального входа через PAM и `pam_access`.

| `pwquality.conf`       | Конфигурация требований к паролям                                          |

## Безопасность и ограничения

- В опубликованной копии `shadow` поля паролей замаскированы.
- Пароли, приватные ключи и токены в репозиторий не включаются.
- Настройки безопасности должны дополнительно проверяться с учётом конкретной инфраструктуры и модели угроз.
